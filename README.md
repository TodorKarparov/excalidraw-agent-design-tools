# Excalidraw Agent Design Tools

A skills-and-helpers plugin for Codex, Claude Code, and Cowork that teaches an agent to produce consistent, readable system-design diagrams in Excalidraw.

## Contents

```text
.
├── .agents/plugins/marketplace.json
├── .claude-plugin/marketplace.json
└── plugins/excalidraw-agent-design-tools/
    ├── .claude-plugin/plugin.json
    ├── .codex-plugin/plugin.json
    ├── package.json
    └── skills/excalidraw-system-design/
        ├── SKILL.md
        ├── references/
        │   ├── assets/icons/aws/
        │   └── guidelines.md
        └── scripts/prepare-components.ts
```

`SKILL.md` defines *how* to work: identify the diagram intent, plan the architecture, plan the layout, render, then review. `references/guidelines.md` defines *what the result should look like*: default flow direction per diagram type, lifecycle outline colours, dashed service boundaries and labels, connector preference order, flowchart conventions, and spacing rules.

## Codex installation

Add this repository as a marketplace, then install the plugin:

```bash
codex plugin marketplace add TodorKarparov/excalidraw-agent-design-tools
codex plugin add excalidraw-agent-design-tools@excalidraw-design-tools
```

Start a new conversation and ask for an Excalidraw architecture diagram, or invoke `@excalidraw-system-design` explicitly.

## Claude Code and Cowork installation

Add the GitHub repository as a Claude marketplace, then install the plugin:

```bash
claude plugin marketplace add TodorKarparov/excalidraw-agent-design-tools
claude plugin install excalidraw-agent-design-tools@excalidraw-design-tools
```

Claude discovers the existing skill automatically from the plugin's conventional `skills/` directory. In Claude Code, invoke it as `/excalidraw-agent-design-tools:excalidraw-system-design` or ask for an Excalidraw architecture diagram and let Claude select it.

In Cowork, open **Customize → Plugins**, add the marketplace from `TodorKarparov/excalidraw-agent-design-tools` (or its GitHub URL), then install **Excalidraw System Design** from the `excalidraw-design-tools` marketplace. Plugin-format compatibility makes the skill and bundled files discoverable in both Claude Code and Cowork; diagram execution still requires the compatible MCP described below.

## Required Excalidraw MCP configuration

The plugin does not bundle or configure an Excalidraw MCP. Installation provides the skill, design rules, icon assets, and TypeScript component helper. Creating or editing a diagram requires a separately configured MCP with the scene-content contract used by the skill and helper, including:

- `edit_scene_content`
- creation and reference through `tempId`
- creation of related elements in the same request
- `startBinding` and `endBinding`
- reciprocal `boundElements`
- returning or preserving the connector targets generated by the component helper

The current workflow matches the Excalidraw+ scene-content API or another MCP that offers the same contract. Compatibility is defined by these capabilities, not by a particular paid or free provider.

The free official service at `mcp.excalidraw.com` currently exposes a different interface based primarily on `read_me` and `create_view`. It is not a drop-in replacement for this plugin's scene-content workflow and must not be configured as though it were. A future adapter could translate the helper's output to `create_view`, but that adapter is outside this milestone and is not included.

Configure a compatible MCP separately in the host where diagrams will be executed, following that MCP provider's connection instructions.

## Node runtime requirement

The bundled `prepare-components.ts` remains the executable source and requires Node.js `>=22.18.0`, where native TypeScript type stripping is enabled by default. The skill tells the agent to check `node --version` before running it and to execute the `.ts` file directly.

In Cowork or another Claude-managed environment, the agent may activate an already-installed Node 22 runtime through `nvm` when available. On a local Claude Code installation, install or activate Node `>=22.18.0` yourself when needed. The skill must not install Node silently or modify local runtime configuration.

## Use

After configuring a compatible Excalidraw MCP, ask the agent for a system-design diagram:

```
Draw an Excalidraw diagram of the order-processing backend:
API gateway -> order service -> payment service, with a retry queue.
Payment service is new, order service is changing.
```

## Conventions at a glance

| Component status | Outline colour |
|---|---|
| Existing and unchanged | Black |
| Existing and changing | Blue |
| New or greenfield | Green |
| To be removed | Red |

- Components are outline-only, never filled.
- Services get a dashed boundary at ~60% opacity, with a larger label above its top-left corner.
- One-way arrows by default; bidirectional communication uses two separate arrows.
- Straight arrow > single-bend elbow > more complex routing. Curves are a last resort.
- Decisions are diamonds; end nodes are black-filled ellipses with white text.

When rules conflict: semantic correctness, then readability, then information hierarchy, then consistency, then aesthetics.
